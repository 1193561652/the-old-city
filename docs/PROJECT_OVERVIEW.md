# The Old City：项目总纲

更新日期：2026-07-13

## 一句话概念

玩家在一座以晚期君士坦丁堡为灵感的衰败古城中，作为城市体系中的一员参与重建与战争；城市资源、军队组织和个人行动共同塑造战局，而世界并不围绕玩家单独运转。

## 核心体验

- 重建：从废墟、破损城墙与失效设施中恢复城市功能。
- 治理：以有限资源在生产、修复、防御和军队之间取舍。
- 守城：面对不断增加的外部压力，让城市系统真正接受检验。
- 多层角色：长期规划包含执政官、将军与战士三种互补视角。

## 玩法结构

### 执政官

负责城市重建、资源配置、建设与宏观防御，是当前 MVP 唯一实现的身份。

### 将军（MVP 后）

负责军队编组、命令、士气、补给与战役执行；不直接承担城市建设。

### 战士（MVP 后）

以第三人称 RPG 方式参与局部战斗、任务和遗迹探索。个人杀敌并不自动决定战争胜负，其价值来自对更大系统的有限介入。

前期一次只扮演一个身份；多角色切换属于远期设计。

## 世界与地图

地图参考晚期君士坦丁堡的空间意象，但不是历史复刻：

1. 前线：古老、破损的多层城墙与敌军来向。
2. 城内：大片衰败但可持续建设、拆除和改造的城区，而非少数固定区域。
3. 后方：港口及与外部资源、补给相关的空间。
4. 遗迹：未来可承载上古知识与 RPG 探索，当前不进入 MVP。

## 系统愿景

### 城市与建筑

RTS 与 RPG 视角必须读取同一建筑状态。`BuildingActor` 的施工状态、进度、资源与事件是唯一事实来源；不同视角只改变表现和交互方式。

### 科学、技术、文化与制度

远期将科学探索与技术应用区分：研究并非支付资源后立即解锁，而可能包含实验、失败、概率结果和副发现。科技、文化与制度形成带滞后效应的反馈网络，例如更自由的文化可能提高长期创新，同时增加短期不稳定。

### 战争

胜负由城市生产、补给、指挥、士气、防御工程与战士行动共同决定。玩家能影响局部，但不是世界唯一的有效行动者。

## 技术原则

- C++：稳定规则、资源账本、建造规则、波次与基础单位逻辑。
- Blueprint：相机手感、建筑预览、HUD、表现和关卡组合。
- DataAsset / DataTable：建筑、单位、波次与平衡参数。
- AI：MVP 先使用 NavMesh、AIController 与简单状态；性能数据证明不足后再考虑 Mass。
- 版本控制：Git；里程碑保留可运行版本。

## 产品边界

本项目是单机游戏。MMORPG 只作为角色成长与世界层次的设计参考，不意味着网络联机或 MMO 规模。
